# Windows Setup Runbook — kr8tiv-mexc-bot

This runbook provisions a fresh Windows 11 machine from zero to a green `pnpm smoke`.
Target time-to-green: ~60 minutes.

## Prerequisites

- Windows 11 (Home or Pro) on x64
- Admin rights on the machine (required for `winget` installs)
- A MEXC account with a trading-only, IP-whitelisted API key (see `docs/phase-1-readiness.md`)

## Step 1. Install core tooling via winget (PowerShell as Admin)

```powershell
# Node 22 LTS
winget install OpenJS.NodeJS.LTS

# Git
winget install Git.Git

# Gitleaks (required for pre-commit hook)
winget install gitleaks.gitleaks

# Memurai Developer (Windows-native Redis, free tier)
winget install MemuraiDeveloper
```

Close and reopen PowerShell so PATH picks up the new tools. Verify:

```powershell
node --version        # expect v22.x.x
git --version         # expect 2.x+
gitleaks version      # expect 8.24+
Get-Service Memurai   # expect Status: Running
```

If Memurai is installed but not running:
```powershell
Start-Service Memurai

```

The PowerShell script reports each prerequisite and Memurai service status.
Fix any [MISSING] items before proceeding.

## Step 6. Provision secrets into Windows Credential Manager

**If you already have the three required secrets stored (the default on Matt's primary machine per STATE.md), skip this step.** Verify with:
```powershell
pnpm verify-env
```
Exit 0 with three [OK] lines = ready.

**If you are provisioning fresh:**
```powershell
pnpm setup:credentials
```
The script prompts for each of:
- `mexc-spot-access` → paste your MEXC spot API key (starts with `mx0`)
- `mexc-spot-secret` → paste the corresponding 32-char hex secret
- `mexc-whitelist-ip` → paste the public IP address you whitelisted on the MEXC key

The script writes them to Windows Credential Manager under service prefix
`kr8tiv-mexc-bot/*`. No plaintext values touch disk outside the OS credential vault.

If your public IP is unknown:
```powershell
(Invoke-WebRequest -Uri "https://api.ipify.org" -UseBasicParsing).Content
```

## Step 7. End-to-end smoke test (FND-08)

```powershell

```

Expected: JSON log lines confirming each boot step, ending with:
- `{"level":30,"msg":"Phase 1 boot complete - all systems ready"}`
- `{"level":30,"msg":"smoke test passed"}`
- Exit code 0

If exit code is:
- **1** → pre-flight failure. Read the fatal log line:
  - `required secrets missing` → run `pnpm setup:credentials`
  - `Redis unreachable` → `Start-Service Memurai`
  - `sqlite open failed` → check `env.SQLITE_PATH` is writable
- **2** → MEXC connectivity failure. Read the fatal log line:
  - `MEXC spot ping failed` → check internet; if `https://api.mexc.com/api/v3/ping` doesn't respond in browser, MEXC may be down
  - `MEXC futures ping failed` → check `https://contract.mexc.com/api/v1/contract/ping`; if 404 or SSL error, the Jan 12 2026 futures domain migration may have landed — update `MEXC_FUTURES_BASE_URL` in `.env.local` to the current domain

## Troubleshooting

- **Git Bash "fork retry" errors** — Known issue on this project. Do NOT use Git Bash for any scripts. Use PowerShell for everything. The pre-commit hook uses lefthook (Rust binary), not husky (shell), so commits still work correctly via PowerShell/Explorer/IDE.
- **`pnpm turbo typecheck` fails on first install** — Reinstall native deps: `pnpm install --force`.
- **Memurai 10-day restart popup** — Expected on the free Developer tier. Restart the service: `Restart-Service Memurai`.
- **Clock skew WARN on smoke** — Run `w32tm /resync` in elevated PowerShell to force NTP sync.
- **IP whitelist mismatch WARN on smoke** — Either (a) MEXC key was whitelisted under a different IP → re-whitelist via MEXC web UI, (b) you're on VPN → disable or re-whitelist the VPN IP.

## Gotchas (re-read before signing)

1. **ISP re-assigns your public IP** — residential IPs rotate on router reboot, modem reset, or whenever the ISP feels like it. If you wake up to `MEXC spot ping failed` the next morning with no code change, your IP rotated. Fix: re-whitelist on MEXC, update `mexc-whitelist-ip` in Credential Manager.
2. **VPN toggling** — connecting/disconnecting a VPN changes your public IP. If you sometimes trade on VPN, whitelist BOTH the VPN IP and your residential IP on MEXC.
3. **90-day expiration for non-whitelisted keys** — does not apply here because you ARE whitelisted. But if the whitelist is ever removed, the clock starts and the key will silently die on day 91.
4. **Key rotation** — if you ever regenerate the MEXC key (e.g., after suspected compromise), update BOTH `mexc-spot-access` and `mexc-spot-secret` in Credential Manager via `pnpm setup:credentials`. A stale key in Credential Manager will show as "present" but fail with `700002 invalid signature` on first API call.
